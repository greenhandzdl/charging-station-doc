# 账户与支付用例

**参与者：** 用户、支付网关、系统

**安全约束：** 密码使用 bcrypt/Argon2 加盐散列存储；所有金额变更写入审计日志；支付回调需签名验证。

> **密码强度规则：** 密码必须至少 8 位，且至少包含大写字母、小写字母、数字、特殊字符（如 !@#$%^&*）中的三种。服务端对注册和修改密码做统一校验。

> **粒度说明：** 总体用例图中"注册/登录"合并为一个用例，表示其在用户视角的入口统一性。具体实现层面，注册与登录分别展开为独立的子流程（如下文所述），各有独立的 API 接口和安全校验逻辑，符合评分标准中功能完整性的要求。

## 注册

1. 未授权用户填写手机号、密码等信息。
2. 系统校验手机号唯一性、密码强度。
3. 系统对密码加盐散列后保存，返回注册成功，新用户身份为普通用户。
4. 维修人员权限需由管理员在后台从用户提升获得。

## 登录

1. 用户输入手机号与密码。
2. 系统验证凭证，校验通过则返回短期凭证（JWT / 会话 Token）。
3. Token 设置有效期，过期后需重新登录。

## 充值

1. 用户发起充值请求，选择支付方式（微信/支付宝/模拟支付）。
2. 系统创建充值记录，状态为 PENDING，等待管理员审批。
3. 管理员审批通过后（PENDING → APPROVED），系统调用支付网关模拟回调处理，状态变为 SUCCESS，余额增加。
4. 审批通过时同时自动检测欠费并补扣。
5. 若管理员拒绝，状态变为 FAILED。
6. 支付回调处理需设计幂等，防止重复入账。
