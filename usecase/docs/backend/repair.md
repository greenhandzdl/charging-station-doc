# 故障报修用例

**参与者：** 用户、维修人员、管理员

## 提交报修

1. 用户、维修人员或管理员在界面提交报修，填写充电桩 ID 与故障描述。
2. 系统生成报修单并将对应充电桩状态设为"故障"。

## 处理报修

1. 管理员查看未处理报修单，通过 `PUT /api/v1/repairs/{id}/assign` 分配处理人员给维修人员（或由管理员直接处理）。
2. 维修人员可通过 `PUT /api/v1/repairs/{id}/claim` 主动接单（自分配），无需管理员指派。
3. 维修人员接收报修任务后开始维修。
4. 完成维修后，操作者提交维修结果。
5. 管理员审核维修结果：
   - 若审核不通过，退回给维修人员返工维修（重复步骤 2-4）。
   - 若审核通过，系统更新报修单状态为"已处理（RESOLVED）"，并关闭（CLOSED）或由管理员直接关闭，充电桩状态恢复为"空闲"。

## 报修单删除

1. 维修人员或管理员可对非 CLOSED 状态的报修单发起删除申请，状态变更为 DELETED（软删除），数据保留。
2. 管理员审核删除申请：
   - 若审批通过，执行硬删除，记录彻底从数据库移除。
   - 若审核不通过，可恢复原状态继续处理。

## 后置条件

报修单记录入库，充电桩状态恢复，记录处理人及时间。软删除记录保留用于审计追溯。
